## 페르소나별 관점

**설계 계약 감사자 (design-contract-auditor)**
- §2-1의 규칙 1~4는 모두 구현됐다. 자신 또는 하위 매칭, 컴포넌트 수가 가장 많은 쪽 선택, 게이트 재정의, 원문 문자열 반환이다. 단위 테스트가 설계 §4에서 요구한 5종(①~⑤)과 1:1로 대응한다. ⑤는 `#[cfg(windows)]`이고 WINDOWS-CHECKLIST §8에도 1줄을 추가했다.
- 게이트 의미는 보존됐다. 운영 경로 두 곳(`jsonl_scan.rs:162`, `mod.rs:166-180`)이 `match_workspace_project(..)?`/`else return false`를 쓴다. `max_by_key`는 후보가 있을 때만 Some이므로 기존 `any(starts_with)`와 동치다. `#[cfg(test)]`로 돌린 래퍼는 기존 회귀 테스트를 보존하는 용도로만 남았다.
- `registry.rs`는 변경되지 않았다. 설계의 "dedup 순서·시그니처 변경 금지" 조항을 지켰다.
- 드리프트는 M2(설계 내부 모순)와 M4(용어 미반영)다.

**화면 상태 정직성 (screen-state-honesty)**
- 상세 세션 섹션은 상태 4종을 올바르게 구분한다. 에러는 errorBlock과 재시도(sessions-error-02 캡처), 미로딩은 loadingBlock, 0건은 범위를 명시한 문구와 "+ 새 세션", 그 외는 목록이다. 홈 타일은 미로딩 시 "—"를 보여준다.
- 서브에이전트 "실행 중" 표시가 없다는 것을 코드에서 확인했다. 설계 §2-3에서 v1 제외로 정한 대로 지켜졌다.
- 남은 정직성 공백은 두 가지다. 목록 화면에서 에러와 0을 구분할 수 없는 것(M2), 그리고 경쟁 상태 때문에 stale "실행 중"이 남을 수 있는 것(M1)이다.

## 잘 된 점

- 판정을 Rust 한 곳에 두고 프론트는 `===`로 조인한다. 이 구조 덕분에 `foo` vs `foo-bar` 같은 판정 어긋남이 구조적으로 생기지 않는다. 그리고 그 불변식을 실데이터 테스트(`mod.rs:260`)로 고정했다.
- 행 렌더러를 `sessionRow.ts`로 옮기면서 홈의 원본과 마크업을 동일하게 유지했고, 모드별 차이는 프로젝트 열 하나뿐이다. noproj 그리드 변형도 열 수가 맞는다(5열에서 4열). 홈 렌더 결과는 running-03 캡처에서 이전과 같다.
- `sessionProjectName`으로 사이드바, 세션 탭, 세션 상세, 홈의 프로젝트명 원천을 projectPath 하나로 맞췄다. 하위 디렉터리 세션도 프로젝트명으로 표시되고, 툴팁에 실제 cwd가 보존된다.
- 카드를 실행 중 우선으로 재정렬하지 않기로 했다(클릭 실수 방지). archived 프로젝트도 정직하게 표시한다. 신규 토큰 없이 기존 Terminus 컴포넌트만 썼다.
