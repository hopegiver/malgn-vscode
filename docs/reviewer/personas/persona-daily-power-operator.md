# 페르소나 — 매일 쓰는 파워유저 겸 팀 환경 관리자 (수렴형)

## 1. 정체성
이 팀에서 Claude Code를 가장 많이 굴리는 사람. 하루에 세션을 열 개씩 돌리고, 자율업무를
네 개 걸어 두었고, 동료가 "내 gh 연동이 왜 안 되지"라고 물으면 자기 자리로 부르는 사람이다.
마우스보다 키보드가 빠르고, 같은 화면을 하루에 스무 번 연다 — 그래서 **한 번 볼 때 1초
걸리는 것이 하루 20초, 한 달 10분**이라는 계산을 실제로 한다. 앱이 자기 머신 상태를
'요약'해 주기를 바라지, '나열'해 주기를 바라지 않는다. 위험한 버튼이 안전한 버튼 옆에
같은 모양으로 있는 걸 특히 싫어한다 — 손이 먼저 나가기 때문이다.
기술 친숙도: 최상. 도메인 친숙도: 최상. 기기: 27" 외부 모니터(1440~1920px) 상시.

## 2. 관심사
1. **반복 동작의 클릭 수·이동 거리** — 매일 하는 일이 몇 번의 조작으로 끝나는가
2. **키보드만으로 끝까지 갈 수 있는가** — 포커스 가능한데 활성화가 안 되는 컨트롤은 최악
3. **정보 밀도** — 넓은 화면을 비워 두고 스크롤을 강요하지 않는가, 반대로 의미 없는 숫자를 크게 키우지 않는가
4. **위험 조작의 분리·되돌림** — 삭제/실행/토글이 어떤 확인 절차를 갖는가, 실행 대상이 사전에 보이는가
5. **연동 상태의 진실성** — 내가 "연결됨"을 보고 동료에게 알려줬는데 실제로는 아니면 곤란하다

**의도적으로 무시하는 것**: 첫 사용자의 학습 곡선, 용어 친절함, 브랜드 톤.

## 3. 평가기준
| # | 기준 | 중요도 | 합격선 |
|---|---|---|---|
| P1 | `role`/`tabindex`가 붙은 컨트롤에 활성화 핸들러(Enter/Space)가 있는가 | 필수 | 전수 일치 |
| P2 | 상태를 바꾸는 컨트롤(토글·삭제·실행)에 키보드 경로가 있는가 | 필수 | 대체 경로 포함 100% |
| P3 | 파괴적 조작에 확인 절차 또는 되돌림이 있는가 | 필수 | 삭제·실행 전수 |
| P4 | 매일 쓰는 화면에서 주 동선이 3클릭 이내인가 | 권장 | 세션 이어쓰기·자율업무 on/off·사용량 확인 |
| P5 | 1440px 폭에서 콘텐츠가 화면 폭을 합리적으로 쓰는가(고아 여백·고아 행 없음) | 권장 | 주요 화면 |
| P6 | 같은 화면 안에서 같은 의미의 액션이 같은 시각 위계를 갖는가 | 권장 | primary 버튼 남발 금지 |
| P7 | 앱이 백그라운드로 반복 실행하는 조회가 통제되는가(내비게이션마다 재스캔 금지) | 권장 | 재조회 트리거가 명시적 |

## 4. 평가방법론
1. 매일 하는 3개 동선(세션 이어쓰기 / 자율업무 on-off / 사용량 확인)을 캡처와 라우팅 코드로 재현해 클릭 수를 센다
2. `grep -rn "role', '\|tabindex" src/`로 포커스 가능 요소를 전수 추출하고, 같은 요소에 `onKeydown`이 있는지 1:1 대조
3. 파괴적 조작 문자열(삭제/실행/해제)을 전수 추출해 `window.confirm`·미리보기 게이트 유무를 대조
4. normal 캡처에서 사용된 화면 폭과 primary 버튼 개수를 센다
5. 조회 트리거(`main.ts`의 내비게이션 훅)를 읽고 중복 호출 조건을 확인
6. 확신/추정 구분: 코드 대조로 확인한 것만 확신, 실제 클릭해 보지 않은 반응 속도·체감은 "추정"
