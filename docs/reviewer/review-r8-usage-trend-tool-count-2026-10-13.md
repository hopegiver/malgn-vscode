## 페르소나별 관점

### claimed-vs-verified — 🟠
- 도구 집계 주장은 관측으로 뒷받침된다. 독립 스크립트 재집계 결과 신규 방식 98,137, 구 방식 18,826이다. 보고값과 같은 규모(약 5.2배 과소 → 해소)이고, 남은 차이는 측정 시점 차이로 보인다(추정: 집계 사이에 로그가 늘었다). Rust 커맨드를 실데이터로 직접 실행해 98,064를 재현하지는 않았다(앱 실기동 미실행). Rust 측은 테스트와 코드 동치성으로만 확인했다.
- 화면 문구는 "원인은 판정하지 않음", "이상치가 없다는 뜻이 아닙니다", "직전 주 0 — % 계산 안 함"처럼 계산 한계를 스스로 밝힌다. 다만 "전주 대비"가 부분일을 품고 있다는 사실은 밝히지 않는다(RV-001).

### async-response-ordering (단일 정의) — 🟢
- 일 토큰 합·캐시 히트율은 앱 전체에서 한 정의다. 추이 모듈은 import 없는 순수 모듈이고 임계값은 `TREND_THRESHOLDS` 한 곳에 모였다.
- "최근 30일"의 날짜 집합이 카드와 추이 사이에서 다를 수 있다(RV-007). 이번 변경 밖의 기존 문제다.
- 비동기 순서 측면: 추이는 이미 로드된 `state.dailyUsage.items`를 렌더 시 동기 계산하므로 새 경쟁 표면이 없다.

### zero-base-redesigner (발산) — 🔵
- **RT-1 (중복 표현)**: 새 30일 막대 차트 바로 아래에 기존 "토큰 사용량 (최근 30일)" 일별 목록이 있다. 같은 일별 합계를 두 번 그리는 셈이다(캡처 01·04). 막대는 클릭되지 않고 목록은 펼쳐지니, 사용자는 어느 쪽이 '진짜'인지 고민하게 된다. **대안 구조**: 막대 차트를 목록의 요약 헤더로 삼는다. 막대를 클릭하면 해당 날짜 행으로 스크롤해 펼치고, 이상치는 목록 행에 ▲/▼ 배지로 단다. 그러면 "이상한 날 → 그 날 세션 상세"가 한 동선이 된다. 새 데이터는 필요 없다.
- **RT-2 (비교 단위)**: RV-001의 근본은 "롤링 7일에 오늘을 넣는다"는 단위 선택이다. **대안 구조**: 주간 표를 "완료된 날 기준"으로 고정하고, 오늘은 별도 '진행 중' 칩(오늘 N 토큰 · 최근 완료 7일 일평균 대비 M%)으로 분리한다. 그러면 "오늘 얼마나 썼나"와 "지난주보다 많이 썼나"라는 두 질문이 섞이지 않는다.

## 트레이드오프
- RV-001 권장안(완료된 7일 비교)과 최소안(라벨 보강)은 비용과 정직성의 교환이다. 권장안은 하네스 기대값 재작성이 따르지만 편향을 없앤다. 최소안은 2줄이지만 오전마다 음수 증감이 뜨는 현상은 그대로다. 소규모 사내 도구라는 점을 감안해도, 이 표의 존재 이유가 "전주 대비"이므로 권장안을 권한다.

## 잘 된 점
- **도구 집계 수정의 범위가 정확하다.** usage는 첫 줄, tool_use는 블록 id 단위로 분리했다. id 없는 블록은 "구분 불가하므로 각각 센다"는 규칙을 명시하고 테스트로 고정했다. summary·detail 두 경로를 같은 식으로 고쳐 정의가 갈라지지 않았다.
- **경계 처리 설계가 모범적이다.** NaN/Infinity 대신 `null + 사유 상태`를 반환하고, 1/3 비교를 곱셈으로 해 부동소수 경계를 없앴다. 중앙값·0인 날 제외의 근거를 주석으로 남겼고, 오늘 급락은 판정하지 않는다. 경계 하네스 65건은 등호 양쪽(899,999/900,000, 99,999/100,000, 룩백 14/15일, 기준선 4/5일)을 모두 찍는다.
- **문구 정직성.** "판정하지 않았습니다 — … 이상치가 없다는 뜻이 아닙니다", "직전 주 0 — % 계산 안 함", 규칙 전문 노출, 원인 미판정 각주가 들어 있다. 데이터 부족과 문제 없음을 구분한다.
- **범위 준수.** 새 커맨드·capabilities·수집 경로가 없고, 기존 `DailyUsage[]`만 재사용한다. Terminus 토큰만 쓰고 새 색은 들이지 않았으며, 색만으로 정보를 전달하지 않는다(▲/▼ 라벨). 데스크톱 고정 폭 레이아웃 안에서 자연스럽다.
