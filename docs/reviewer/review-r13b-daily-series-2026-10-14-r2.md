## 페르소나별 관점

### claimed-vs-verified — 🟢
- 커밋 메시지의 세 주장(RV-001 라벨, RV-002 fmtCost와 "추정", RV-004 박스 제목)은 모두 코드 라인과 캡처로 확인했다. 반영 범위도 주장과 일치한다. 차트 버튼처럼 바꾸면 안 되는 곳은 바꾸지 않았다.
- 카드 주석(`usage.ts:430-434`)이 새 동작(≥, "추정")을 정확히 서술한다. 남은 불일치는 다른 파일의 주석 2곳뿐이다(RV-006).

### async-response-ordering (단일 정의) — 🟢
- 이제 같은 화면의 모든 비용 값이 같은 ≥ 규칙을 쓴다. 대상은 카드, 주간 표, 차트, 일별 목록, 오늘 줄이고, 함수는 `fmtCost` 하나다. 직전 라운드에 확인한 일별 합 = 요약 합 불변식에는 이번 커밋이 손대지 않았다(Rust 변경 없음).

### zero-base-redesigner (발산) — 🔵
- RT-1: "세션 수(일별 합)"이라는 라벨은 정직하다. 하지만 사용자가 알고 싶은 것은 "이번 주에 세션을 몇 개 했나"다. 라벨이 이 질문에 답하지 못한다는 사실을 밝혔을 뿐이다. 대안 구조는 그대로 유효하다. 사용자 피드백을 본 뒤 결정해도 된다.
- RT-2: 카드가 `fmtCost`로 들어오면서 "≥ 누락"이라는 실제 결함은 사라졌다. 남은 것은 구조적 취약성뿐이라 이월이 타당하다.
