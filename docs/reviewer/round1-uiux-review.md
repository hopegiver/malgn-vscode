## 요약 (2분 규칙)

기능은 실제로 거의 다 붙어 있고, 잘 만든 화면(프로젝트 목록·카탈로그·자율업무·세션 상세)은
이미 조직 표준으로 삼을 만하다. **이번 라운드의 유일한 관통 문제는 "3상태(로딩/빈/에러)를
화면마다 손으로 짜서, 어떤 화면은 실패를 0으로 바꿔 말한다"는 것**이다. 특히 로그인 직후
첫 화면인 대시보드는 조회가 실패해도 "설치된 플러그인 0개 (실제 로컬 데이터)"라고 단정한다
(`r1__home__error.png`) — 사내 개발자가 이걸 믿고 재설치 절차를 밟으면 그 시간이 그대로
비용이다. 두 번째로, 목업 시대의 잔재(안 되는 저장 버튼, "(실제 로컬 데이터)" 라벨 6회 반복)가
아직 화면에 남아 신뢰를 갉아먹는다. 나머지는 대부분 CSS 1~2줄짜리 시각 결함이거나
값어치가 낮아 보류를 권하는 항목이다.

- **잘 된 점**: 다크 사이드바 + 밝은 캔버스 + 인디고 강조의 톤이 19개 화면 전체에서 흔들림 없이 유지된다. 카드 radius·hairline·muted 색 위계도 일관적이다. 이 정도 일관성을 프레임워크 없이 유지한 것은 칭찬할 만하다.

## 트레이드오프 (페르소나 간 충돌)

1. **파워유저 "정보 밀도를 높여라" vs 신입 "설명을 붙여라"** — 대시보드에서 정면충돌한다. 파워유저는 숫자 7개도 낭비라 하고, 신입은 그 숫자가 뭘 뜻하는지 모르겠다고 한다.
   → **권고: R-01(조치 필요 항목 중심)을 택한다.** 두 요구를 동시에 만족하는 유일한 안이다 — 파워유저에게는 스캔할 것이 줄고, 신입에게는 "지금 해야 할 일"이 문장으로 주어진다.
2. **시각 감사관 "토큰 체계를 세워라" vs 조직 규모(50인 미만 내부 도구)** — U-12(폰트 15종)·spacing 토큰이 여기 걸린다.
   → **권고: 부분 채택.** 2회 이상 실제로 반복된 값(warning 3색, U-11)만 토큰화하고, **spacing 토큰은 도입하지 않는다.** 폰트는 다른 항목이 끝난 뒤 여유가 있을 때만.
3. **상태정직성 "모든 화면에 3상태를 다 넣어라" vs 파워유저 "안 일어나는 상태에 시간 쓰지 마라"** — U-04(dev-tools 빈 상태)가 대표 사례로, 백엔드가 고정 6종을 돌려주므로 실제로는 거의 발생하지 않는다.
   → **권고: R-03(공용 헬퍼)으로 우회한다.** 헬퍼를 쓰면 "발생 빈도가 낮은 상태"도 추가 비용 없이 따라오므로 이 충돌 자체가 사라진다. 헬퍼 도입 전이라면 U-04는 후순위로 미뤄도 좋다.

## 잘 된 점 (다음 산출물의 기준)

1. **프로젝트 목록 화면 = 3상태 처리의 사내 표준.** 스켈레톤 → 3요소 빈 상태 → 원인 경로가 담긴 `alert` + '다시 시도'까지 완비(`r1__projects-list__{loading,empty,error}.png`). 다른 화면을 고칠 때 여기를 베끼면 된다.
2. **에러 문구가 원인 위치를 말한다.** "`~/workspace` 디렉터리를 읽는 중 권한이 거부되었습니다 (EACCES)", "`installed_plugins.json` 파일을 파싱하지 못했습니다 (JSON 문법 오류)" — 사내 개발자 대상으로는 이보다 나은 에러 문구를 설계하기 어렵다.
3. **파괴적 조작 3곳(자율업무 삭제·MCP 삭제·CLI 설치/업데이트)에 전부 확인 절차가 있다.** 특히 devTools의 dry-run 미리보기 → 영향 항목 나열 → 신뢰도 경고 → planId 확인 실행은 이 앱 최고의 흐름이다.
4. **"거짓 표시 금지" 원칙이 코드 주석과 실제 구현에 함께 살아 있다.** `dom.ts:38-44`의 `liveIndicator`는 워처 구독이 실제 성공했을 때만 켜지고, 세션 상세는 `turnId` 유무로 "조회 실패"와 "아직 jsonl이 없을 뿐"을 구분한다(`sessions.ts:570-576`). U-01의 위젯들이 이 원칙에서만 이탈한 것이므로, 조직 문화가 아니라 개별 누락으로 판단한다.
5. **캡처 하네스 자체가 이번 리뷰를 가능하게 했다.** 75장 · 실패 0 · pageerror 0에 `verify()`까지 붙어 "찍기만 하고 끝"내지 않았고, `quirk`와 실패를 구분한 것도 정확한 설계다. 이 자산은 라운드 2·3에서 before/after 대조로 계속 쓸 것을 권한다.
6. **톤앤매너 일관성.** 19개 화면 전부에서 사이드바·카드·배지·hairline 위계가 흔들리지 않는다.
