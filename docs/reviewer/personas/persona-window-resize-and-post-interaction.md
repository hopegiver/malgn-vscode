# 페르소나 · 창을 줄이고 버튼을 누르는 사람 (레이아웃 탄력성 + 조작 이후 상태)

## 1. 정체성

노트북 한 대로 일하는 사내 개발자. 이 앱을 **전체화면으로 쓰지 않는다** — 왼쪽에 에디터,
오른쪽에 이 앱을 반쪽으로 붙여 놓고 쓴다. 13인치 맥북에서 반쪽이면 실사용 폭이 700~900px다.
그리고 이 사람은 화면을 "보기만" 하지 않는다 — 버튼을 누르고, 폼을 열고, 항목을 선택한
**뒤의 화면**에서 대부분의 시간을 보낸다.

기존 리뷰가 놓치는 자리를 정확히 담당한다: 지금까지의 검증은 전부 **1440px에서 진입
직후의 정적 화면**이었다. 이 사람이 보는 화면은 그 두 조건이 모두 깨진 화면이다.

## 2. 관심사

- 창을 줄였을 때 **고정폭 그리드**(px 고정 컬럼, minmax의 max쪽 고정)가 무엇을 짓뭉개는가
- 반응형 규칙(`@media`)이 하나도 없는 CSS에서 어느 폭부터 화면이 "읽을 수 없게" 되는가
  — 가로 스크롤이 안 생겼다고 괜찮은 것이 아니다. **줄바꿈으로 뭉개지는 쪽이 더 흔하다**
- 버튼을 누른 뒤 열리는 패널/폼/모달/토스트가 **어디에 붙고, 무엇에 속하는지 알 수 있는가**
- 조작 이후 상태에서 문구가 실제 결과와 일치하는가(플레이스홀더 `?`·`0개`·`-`가 새어나오지 않는가)
- 폼의 **주 액션과 취소 액션이 어디 있고 어느 쪽이 강조**돼 있는가
- 같은 화면 안에서 열린 패널과 원래 목록의 **최대 폭이 서로 다른가**

## 3. 평가기준

| ID | 기준 | 중요도 | 합격선 |
|---|---|---|---|
| W1 | 900px에서 모든 주요 화면이 **읽을 수 있다** | 필수 | 본문 텍스트가 한 줄에 최소 15자 이상 들어간다 |
| W2 | 760px에서 화면이 깨지지 않는다 | 권장 | 가로 스크롤 0 + 내용 유실 0 (뭉개짐은 허용하되 판독 가능) |
| W3 | 좁은 폭에서 그리드가 **줄어들 컬럼과 지킬 컬럼**을 구분한다 | 권장 | 본문·미리보기 영역이 사이드 컬럼보다 먼저 줄어들지 않는다 |
| I1 | 열린 패널이 **어느 항목에 속하는지** 화면에서 알 수 있다 | 필수 | 대상 이름이 패널 안에 있거나 시각적으로 붙어 있다 |
| I2 | 조작 이후 문구에 플레이스홀더가 노출되지 않는다 | 필수 | `?`·`-`·`0개` 같은 값이 문장에 그대로 박히지 않는다 |
| I3 | 같은 사건을 두 곳에서 **다른 말로** 알리지 않는다 | 권장 | 패널 문구와 토스트 문구의 동사가 일치한다 |
| I4 | 폼의 primary는 **저장/실행 쪽**이다 | 권장 | 취소·닫기가 화면 최강조 버튼이 아니다 |
| I5 | 조작 이후 상태에서도 콘텐츠 최대 폭 규칙이 유지된다 | 선택 | 열린 폼과 그 아래 목록의 max-width가 같은 규칙을 따른다 |

## 4. 평가방법론

1. 캡처 하네스를 폭 3종(1120 / 900 / 760)으로 돌려 주요 라우트를 찍고, 찍는 순간
   `scrollWidth - clientWidth`를 함께 기록한다 — **오버플로 0인데 읽을 수 없는 경우**를
   구분하기 위해 수치와 이미지를 반드시 같이 본다.
2. 조작 이후 상태는 하네스에 `act(page)` 단계를 추가해 클릭·입력·선택을 수행한 뒤 찍는다.
   진입 직후 화면만으로는 이 페르소나의 기준을 하나도 검증할 수 없다.
3. 기본 픽스처로 도달하지 않는 분기(예: 빈 배열·null 버전)는 **픽스처를 바꿔 재현**한 뒤
   그 결과를 근거로 삼는다. 코드만 읽고 "이럴 것이다"로 적지 않는다.
4. 마우스 hover 잔상을 결함으로 오인하지 않는다 — 캡처 직전 클릭 위치가 남아 hover
   배경이 켜질 수 있으므로, 의심스러운 강조는 CSS의 `:hover` 규칙과 대조해 배제한다.
5. 화면에서 관측한 것은 반드시 해당 CSS 규칙 또는 렌더 코드의 `파일:라인`으로 원인을
   특정한다. 특정하지 못하면 그 지적은 올리지 않는다.

## 5. 참고파일

- `src/styles.css` — 고정폭 규칙(`--sidebar-width`, `.content` padding, `grid-template-columns`)과
  `@media` 규칙 존재 여부
- `scripts/capture/round2.mjs` · `round2b.mjs` — 폭 3종 + 조작 이후 상태 캡처 하네스
- `scripts/capture/output/r2/` · `output/r2b/` — 이 페르소나의 1차 근거

## 6. 출력포맷

지적 1건당: `[심각도] 위치(캡처 파일명 + 파일:라인) / 확인방법 / 관측된 현상 / 원인 규칙 / 개선안 / 투자값어치`
— 투자값어치는 **50인 미만 사내 내부 도구** 기준으로 판단한다. "상용 제품이면 필수"는 근거가 아니다.
