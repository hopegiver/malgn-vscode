# Windows 실기 확인 체크리스트

macOS 개발 환경과 CI(`windows-latest`)로는 검증할 수 없는 항목만 모았다. CI는 **컴파일과 단위 테스트까지만** 보증한다 — 실제 창·UAC·설치 거동은 실기에서만 확인된다.

대상 버전: **v0.2.7** 이상. 확인 결과는 malgnai-hub 이슈에 남기거나 개발팀에 전달한다.

---

## 1. 기본 동작

- [ ] `malgn-agent_0.2.7_x64-setup.exe` 설치가 정상 완료된다
- [ ] 앱 실행 중 **콘솔(검은) 창이 뜨지 않는다**
  - 특히 **개발 환경 화면 진입 시** — 여기서 CLI 6종의 버전을 한꺼번에 조회한다
  - 뜬다면 몇 개가, 어느 화면에서 뜨는지 기록
- [ ] 창을 최대한 작게 줄여도 **900×600 아래로 내려가지 않는다**
- [ ] 자동 업데이트 알림이 뜨고, 업데이트가 정상 적용된다

## 2. 개발 도구 설치 (v0.2.5에서 새로 열린 경로)

- [ ] **Node.js / Git에 "필수" 배지**가 보이고, 미설치면 눈에 띄게 표시된다
- [ ] Node·Git·pnpm에 **설치 버튼**이 보인다(winget이 있는 환경)
- [ ] 설치 버튼 → 미리보기에 **실행될 명령 전문**과 "미리 확인할 수 없다"는 경고가 함께 뜬다
- [ ] 미리보기 문구에 **관리자 권한(UAC) 안내**가 포함돼 있다
- [ ] 실행 시 **UAC 창이 뜨고, 승인하면 설치가 완료**되어 목록이 "설치됨"으로 바뀐다

### 아래 셋은 결과를 꼭 기록해 주세요 — 코드가 이 답을 기다리고 있습니다

- [ ] **UAC를 취소했을 때의 종료 코드** — `-1978334964`인가 `-2147023673`인가?
  - 현재는 두 경우를 모두 포괄하는 완곡한 문구를 쓰고 있다. 확정되면 정확한 문구로 바꿀 수 있다
- [ ] **Git이 어디에 설치되는가** — `C:\Program Files\Git`(머신)인가 `%LOCALAPPDATA%\Programs\Git`(사용자)인가?
  - 사용자 스코프면 UAC 자체가 안 뜬다. 안내 문구를 그에 맞게 고칠 수 있다
- [ ] **Node가 어떤 형태로 설치되는가** — 설치 후 앱이 "설치됨"으로 인식하는가, 아니면 "설치 확인에 실패했습니다"가 뜨는가?
  - 후자면 portable(zip) 변형이 선택된 것이라 탐지 경로를 추가해야 한다

### winget이 없는 구형 Windows라면

- [ ] "안내 보기"에 **winget이 없다는 이유**와 복사 가능한 설치 명령이 뜬다

## 3. v0.2.4에서 고친 것 — 재발하지 않는지

- [ ] **카탈로그에서 플러그인 설치가 성공**한다
  - 실패하면 `claude`가 어디에 설치돼 있는지 알려주세요(네이티브 exe / npm shim / winget)
- [ ] **자율업무 화면에 프로젝트가 보인다**
  - 설정에서 workspace 경로를 `~\workspace`처럼 **역슬래시**로 넣어도 인식되는가
  - 안 보이면: 그 폴더 안에 `CLAUDE.md`가 있는지 확인. 없으면 정상 동작이며, 화면이 그 이유를 알려줘야 한다
- [ ] `claude` 로그아웃 상태에서 새 세션을 시도하면 **"터미널 열기 (claude login)" 버튼**이 뜬다
  - 버튼을 누르면 PowerShell 창이 열리고 `claude login`이 실행되는가
- [ ] 오류 메시지가 뜬 뒤 **사라지지 않고 남아 있다**
- [ ] 마켓플레이스 설정에 **"맑은소프트 마켓플레이스 추가"** 안내가 뜨고, 버튼 한 번으로 추가·제거된다

## 4. v0.2.6~v0.2.7에서 고친 것 — 재발하지 않는지

- [ ] **설정을 입력하는 도중 값이 사라지지 않는다**
  - 확인법: OTel 주소나 MCP 서버 이름을 **절반만 입력한 채 1~2분 두었다가** 이어서 입력
  - 개발 도구 설치를 걸어둔 상태에서 동시에 입력해 보면 더 확실하다
- [ ] 긴 텍스트 중간에 커서를 두고 기다려도 **커서가 끝으로 튀지 않는다**
- [ ] 프로젝트·세션이 **0건일 때 "불러오는 중…"이 아니라 "없습니다"**로 표시된다
- [ ] 모달을 연 뒤 **Tab을 여러 번 눌러도 모달 밖으로 빠져나가지 않는다**
- [ ] 로그아웃 후 다시 로그인했을 때 **이전 대화·목록이 남아 있지 않다**
- [ ] 카탈로그의 에이전트·스킬에 **이름과 함께 설명이 보인다**
- [ ] 세션 제목이 길어도 **"메타데이터" 버튼이 찌그러지지 않는다**
- [ ] 창을 좁혀도 이름 옆 배지가 **두 줄 사이에 끼지 않는다**

## 5. 오래 걸리는 확인

- [ ] 자율업무를 실행·종료한 뒤 **작업관리자에 `claude` 프로세스가 남지 않는다**
- [ ] 세션 목록이 **종료된 작업의 정보로 덮어써지지 않는다**
- [ ] 개발 환경 화면에서 **CLI 6종 버전이 모두 정상 표시**된다
  - nvm-windows·Volta·Scoop·fnm으로 Node를 관리 중이면 실패할 수 있다(탐지 후보가 표준 경로 2곳뿐)
- [ ] Google 로그인이 **실계정으로 동작**한다(지금까지 개발용 우회만 검증됨)
- [ ] 자율업무가 오래 안 돌면 **"예약된 자율업무가 실행되지 않고 있습니다"** 배너가 뜬다

## 6. IT 담당자 — 루트 CA 배포

설치 파일은 사내 자체 루트 CA로 서명돼 있다. 그 CA가 없는 PC에서는 SmartScreen 경고가 그대로 뜬다(설치는 가능, 경고만 넘기면 된다).

- [ ] 루트 CA 공개 인증서(`.cer`) 확보 — **아직 아무도 갖고 있지 않다**
  - 게시된 exe에서는 추출할 수 없다(Authenticode가 루트를 담지 않는 정상 동작)
  - `WINDOWS_CERTIFICATE` 시크릿을 처음 등록한 담당자가 원본을 갖고 있을 가능성이 높다
  - 절차: `docs/RELEASE.md` 3-1
- [ ] 확보 후 45대에 배포 — `certutil -addstore Root` 또는 그룹 정책(`docs/RELEASE.md` 3-2)
