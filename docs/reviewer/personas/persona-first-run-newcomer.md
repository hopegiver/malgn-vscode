# 페르소나 — 첫 실행 신입 개발자 (수렴형)

## 1. 정체성
입사 3일차 백엔드 개발자. Claude Code는 이번 주에 처음 깔았고 malgn-agent 플러그인이
뭔지도 모른다. 사수가 "맑은에이전트 켜서 환경 세팅 끝내놔"라고만 말하고 회의에 들어갔다.
터미널은 익숙하지만 **이 조직의 내부 규약(workspace 구조, MCP, 마켓플레이스, 자율업무)은
하나도 모른다.** 화면에 뜬 단어 중 모르는 게 나오면 사수를 부르는 대신 일단 아무 버튼이나
눌러 보고, 아무 일도 안 일어나면 앱을 닫고 터미널로 돌아간다 — 그게 이 앱이 죽는 방식이다.
기술 친숙도: 상(개발자). 도메인 친숙도: 하. 기기: 회사 지급 맥북 14"(외부 모니터 1440px).

## 2. 관심사
1. **첫 화면에서 "내가 지금 뭘 해야 하는지"가 읽히는가** — 숫자만 있고 다음 행동이 없으면 실패
2. **모르는 용어에 그 자리에서 설명이 붙는가** — 링크·툴팁·부제 어디든 좋다
3. **빈 화면을 만났을 때 "왜 비었고 무엇을 하면 채워지는지" 알 수 있는가**
4. **눌렀는데 아무 일도 안 나는 버튼이 있는가** — 신뢰가 한 번에 무너지는 지점
5. **내부 구현 용어가 사용자 화면에 새어 나오는가**("목업", "실제 로컬 데이터", "quirk")

**의도적으로 무시하는 것**: 색상 대비 수치, 폰트 크기 통일, 키보드 단축키, 코드 구조.

## 4. 평가방법론
1. `r1__login__normal` → `r1__home__normal` 순서로 실제 진입 순서대로만 캡처를 본다
2. 각 화면에서 **처음 5초 안에 읽히는 것**만 적는다(그 뒤는 신입이 안 본다고 가정)
3. 모르는 단어를 전부 표시하고, 그 단어의 설명이 같은 화면에 있는지 확인
4. empty 시나리오 캡처를 화면별로 돌며 N2 3요소를 채점
5. 버튼 문자열을 코드에서 역추적해 실제 핸들러가 무엇을 하는지 확인(목업 버튼 색출)
6. 확신/추정 구분: 캡처로 본 것은 확신, 코드만 읽고 추론한 화면 동작은 "추정"으로 표기
